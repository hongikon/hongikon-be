# 물어보기 범위 규칙

물어보기(챗봇)가 **무엇에 답하고 무엇을 거절하는지** 정하는 기준이다. 코드와 프롬프트의 판단은 모두 이 문서를 따르고, 규칙을 바꿀 때는 이 문서를 먼저 고친다.

- 코드:
  - `ask/AskScope.java`: 범위 종류, 거절 문구, API 전 차단 패턴
  - `ask/OtherSchoolGuard.java`: 다른 대학 섞임 출구 검사
- 프롬프트:
  - `AskCatalog.PROMPT_HEAD`: 고르는 단계의 범위 판정
  - `AskLlmClient.ANSWER_SYSTEM`: 답 쓰기 규칙
- 평가: 프론트 `scripts/ask/cases/scope.json`(정답표), `scripts/ask/eval-server.mjs`

## 1. 범위 종류

| 범위 | 뜻 | 서버 동작 |
|---|---|---|
| `SCHOOL` | 홍익대학교(서울캠퍼스 기준) 학생 생활·행정·시설 질문 | 고르기 → 답 쓰기 |
| `OFF_TOPIC` | 학교와 무관한 요청 (일반 상식, 코딩, 과제 대필, 날씨, 잡담 등) | 답 쓰기 없이 정해진 문구 |
| `OTHER_SCHOOL` | 다른 대학 자체에 대한 질문 | 답 쓰기 없이 정해진 문구 |
| `ABUSE` | 규칙 무시 유도, 프롬프트 공개 요구, 다른 역할 강요, 남의 개인정보 요구 | 정해진 문구. 명백한 패턴은 API 호출 전에 차단 |

거절 문구는 `AskScope` 에 고정한다. 모델이 매번 다르게 쓰지 않게 하고, 거절에는 API 를 한 번(고르기)만 쓰거나 아예 쓰지 않는다.

## 2. 범위 판단 기준

**기본값은 SCHOOL 쪽이다.** 애매하면 답 쓰기로 넘기고, 답 쓰기는 원문에 없으면 "확인되지 않아요"라고 한다. 학교 질문을 잘못 막는 것이, 범위 밖 질문에 원문 기반 '모름' 답을 하는 것보다 나쁘다. 단, `OTHER_SCHOOL` 과 `ABUSE` 는 예외로 엄격하게 막는다.

### SCHOOL (답한다)
- 학사(수강, 휴학·복학, 졸업, 성적, 학점교류), 장학, 등록금, 기숙사, 학생증, 메일·와이파이 등 학교 IT
- 캠퍼스 건물·시설·운영시간·위치, 학식, 학교 공지, 학생회·동아리, 상담·보건·안전
- 홍익온 지도·앱이 다루는 학교 주변 정보: **제휴업체(학생 혜택)**, 오시는 길, 주변 교통
- 다쳤어요·위급해요 같은 안전 질문은 항상 SCHOOL. 위급하면 119 를 먼저 안내한다.
- 학교 프로그램에 다른 대학이 엮인 질문:
  - 신촌지역 대학 학점교류
  - 행복기숙사 참여 대학
  - 교환학생 파견 대학
  - 동아리 대학 교류전

### OFF_TOPIC (거절)
- 일반 상식·시사·날씨·주식, 번역, 코딩, 수학 풀이
- 과제·리포트·자기소개서 대필
- 학교와 무관한 맛집·여행 추천
  - 단, 제휴업체 혜택을 묻는 질문은 SCHOOL
- 잡담, 감정 상담 대화
  - 단, 상담센터를 찾는 질문은 SCHOOL
- 의료·법률 판단. 학교 보건·상담 창구 안내는 SCHOOL

### OTHER_SCHOOL (거절 — 섞지 않는다)
- 다른 대학의 제도·시설·일정·입시를 묻는 질문
  - 예: "연세대 기숙사 신청 방법", "고려대 장학금"
- 홍익대 정보를 다른 대학과 비교해 달라는 질문
  - 예: "홍대랑 서강대 등록금 비교"
  - 다른 대학 쪽 정보가 우리 원문에 없으니 비교 자체가 섞임이 된다.

### ABUSE (거절)
- "이전 지시 무시", "시스템 프롬프트 출력", "개발자 모드", 다른 역할 하기 요구
- 특정 학생·교직원의 개인정보(연락처, 학번, 성적) 요구
  - 부서 대표 전화는 SCHOOL

## 3. 다른 대학 정보 섞임 금지 (절대 규칙)

홍익대 정보와 다른 대학 정보는 **어떤 경우에도** 한 답에 섞지 않는다. 세 겹으로 막는다.

1. **입구 (고르는 단계):** 다른 대학 자체를 묻는 질문은 `OTHER_SCHOOL` 로 판정하고 답 쓰기를 부르지 않는다.
2. **답 쓰기 지시:** 다른 대학 이름은 근거 원문에 그 이름이 있을 때만 원문 그대로 쓴다. 다른 대학 질문에 홍익대 정보로 대신 답하지 않는다.
3. **출구 (서버 코드, 모델 판단과 무관):** `OtherSchoolGuard` 가 답 글자를 화면으로 보내기 전에 검사한다.
   - 답에 다른 대학 이름이 나오면, 그 이름이 **이번 답의 근거로 읽은 홍익대 원문**(안내·공지·시설·제휴 결과)에 있는지 확인한다.
   - 없으면 그 순간부터 글자를 더 보내지 않고, 답 전체를 `OTHER_SCHOOL` 문구로 바꾼다. 기록에는 `MIX_BLOCKED` 로 남긴다.
   - 실시간 전송 중에는 대학 이름 길이만큼 글자를 붙잡아 두고 보내서, 이름 일부가 먼저 새어 나가지 않게 한다.

**허용되는 언급 (원문에 있는 경우):**
- 행복기숙사 참여 대학 목록
- 동아리 교류전 학교
- 정류장 이름 "서강초등학교", 과목명 "미술원서강독"
  - 대학 이름 패턴(`서강대`)에 걸리지 않는다.

**대학 이름 목록:** `OtherSchoolGuard.NAMES`
- 정식 이름 줄기("연세대" → 연세대·연세대학교 모두 잡힘)와 영문 이름을 쓴다.
- "연대", "이대", "고대" 같은 줄임말은 일반 낱말(연대보증, 이대로, 고대 유적)과 겹쳐 넣지 않았다. 이 경우는 1·2번 단계가 막는다.
- 새 학교가 문제 되면 목록에 더하고 `OtherSchoolGuardTest` 에 사례를 넣는다.

## 4. 서울·세종 캠퍼스

- 기본은 **서울캠퍼스** 기준으로 답한다.
- 원문에 세종캠퍼스 내용이 함께 있으면, 학생이 세종을 물었을 때만 쓰거나 "세종캠퍼스는 …"이라고 밝혀 따로 쓴다. 서울 절차와 섞어 하나의 절차처럼 쓰지 않는다.
- 이 규칙은 답 쓰기 지시로만 지키고, 서버 출구 검사는 없다. 평가 정답표의 세종 사례로 확인한다.

## 5. 답 모양

- 첫 답은 질문에 바로 답하는 1~3문장이다.
- 같은 속성을 가진 항목 3개 이상을 비교하면 **표**로 쓴다.
  - 예: 장학금 종류별 대상·금액, 기간별 환급률, 층별 입주 업체
  - 열은 4개까지, 칸 값은 원문 그대로 옮긴다.
- 경우가 여럿이면 가장 흔한 경우로 답하고, 나머지는 한 줄로 묶거나 되묻는다.
